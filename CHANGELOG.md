# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Initial repository scaffold: pnpm workspaces mono-repo (`server`, `cli`, `client`, `shared`).
- TypeScript strict configuration (`tsconfig.base.json`).
- ESLint flat config + Prettier + husky pre-commit hooks.
- GitHub Actions PR workflow (typecheck + lint).
- Issue templates, pull request template, CODEOWNERS.
- Apache License 2.0 + NOTICE.

### Changed

- **Persistence strategy (architectural):** SQLite is now the default database (zero-infra, CLI-driven). PostgreSQL becomes opt-in for Docker / production deploys. The persistence layer is built on [Kysely](https://kysely.dev) (multi-dialect, type-safe SQL) so the same code runs on both backends. PostgreSQL ships working in v0.1.0 but is officially validated in CI starting v0.1.1.
- **Internal imports use the Node `imports` field aliases** (PRY-009): cross-module imports inside `@hive/server` now use `#persistence/*`, `#domain/*`, `#observability/*` instead of `../../`. ESLint `no-restricted-imports` enforces the convention — relative cross-module specifiers fail CI. Per ADR-009.

### Added (v0.1.0 progress)

- **Auth + Identity subsystem** (PRY-002): 7-step JWT verifier with full mapping of `jose` exceptions to 13 semantic error codes; Ed25519 keypair store with `kid` derived from SPKI DER bytes; persistent + in-memory blocklist; issuer / rotator / revoker with atomic transactions. Per [ADR-007](https://github.com/hivemine-ai/hive-vault) (CallerContext) and [ADR-008](https://github.com/hivemine-ai/hive-vault) (persistence layer).
- **Admin participant management** (PRY-002): `createHivekeeper`, `createAgent` (with cross-domain hook for Cell Store), `revokeAgent` (idempotent), `listAgents` and `listHivekeepers` with portable keyset pagination.
- **`hivectl init`** (PRY-002): bootstraps a fresh Hive end-to-end on SQLite (default) or Postgres. Idempotent against a non-empty DB (throws `HIVE_ALREADY_INITIALIZED`).
- **Persistence layer foundation** (PRY-002): Kysely + dialect detection (`createDb`), portable `acquireLock` primitive (replaces `pg_advisory_lock`), `Kysely.Migrator` with static migration catalog, type mappers for ISO 8601 timestamps + JSON snapshots.
- **Per-package READMEs** and `docs/` user-facing component documentation, anchored on [`docs/auth.md`](./docs/README.md).
- **Cell Store + Message Persistence Slice 0** (PRY-003): mailbox-per-participant subsystem materialized end-to-end. Schema (4 tables: `cells`, `messages`, `retention_policies`, `idempotency_keys`) with portable partial indexes for the unread / expired hot paths. Domain operations: `sendMessage` (full precondition catalog + idempotency replay + atomic INSERT + post-commit `messageDelivered` event), `readMailbox` (keyset pagination, on-read filter of expired), `markRead` (atomic UPDATE with uniform privacy). Cross-PRY ops: `summarizeUnreadForCell` (consumed by Waggle in PRY-004) and `findMessageById` (consumed by MCP `reply_to` in PRY-005). Visibility check pluggable via injected `VisibilityEngine` (Slice 0 wires the `stubVisibilityEngine`; real impl lands in PRY-008). Cross-domain hook from Auth fully wired: `createHivekeeper` and `createAgent` now create the participant's Cell within the same transaction; `revokeAgent` closes it atomically. Per [ADR-002](https://github.com/hivemine-ai/hive-vault), [ADR-003](https://github.com/hivemine-ai/hive-vault), [ADR-005](https://github.com/hivemine-ai/hive-vault) and the [Cell Store + Message Persistence](https://github.com/hivemine-ai/hive-vault) tech spec.
- **`#composition/*` import alias** (PRY-003): added to `packages/server/package.json` `imports` field so the new `composition/` subdirectory (cross-domain hook adapter, visibility stub) is reachable cross-module under the same convention as `#persistence/*`, `#domain/*`, `#observability/*`. Per ADR-009.
- **`revokeHivekeeperWithCascade` admin operation** (PRY-010): atomic cascade revocation — Hivekeeper + all owned Agents transition to `state='revoked'` and their Cells transition to `state='closed'` in a single transaction. Snapshots the effective retention policy on the keeper's row at revocation time so post-revocation reads see frozen retention semantics. Idempotent: a second call on an already-revoked keeper returns empty counts. Defense-in-depth guard rejects an Agent id with `INVALID_STATE_TRANSITION{target_is_agent}` (mirrors `revokeAgent`'s symmetric guard). Surface-only for now — `hivectl` CLI command exposing it lands in PRY-007.
- **Visibility Engine + Audit Log Slice 0** (PRY-004): authorization layer that protects every send. `canSend(input)` evaluates the 18-row product matrix (data-driven `Map<sender|recipient, MatrixRow>` with default-deny fall-through), resolves the recipient via `participantsRepo.findById`, and writes a `visibility_denial` audit row for every deny — invariant: no deny path returns without auditing. `canSee(input)` derives directory visibility from product principles (Workers private to owner scope, Scouts public, Hivekeepers visible to Hivekeepers); audit of canSee denials is opt-in via `HIVE_VISIBILITY_AUDIT_CANSEE_DENIALS=true` (default false). `audit_log` table (append-only) carries 18 categories — visibility denials plus admin op categories that other domains will register from Slice 1+. The recorder is fire-and-forget with a strict failure-mode contract: on INSERT failure it writes a structured stderr entry + increments the per-category counter and never propagates to the caller, so a DB outage in the audit path does not abort the originating operation. Detail field capped at 4096 bytes (CHECK constraint + app-side `validateJsonText`); oversize details are dropped, the row still persists with NULL detail. Composition root `createVisibilityEngineForProduction` replaces the always-allow `stubVisibilityEngine` from PRY-002 (the stub remains available for Cell Store unit tests). The full `queryAuditLog` with paginated cursor + `streamAuditLog` + `purge-job` ship in Slice 1; user-facing operator surface ships when `hivectl audit query` lands in PRY-006. Per [ADR-002](https://github.com/hivemine-ai/hive-vault), [ADR-003](https://github.com/hivemine-ai/hive-vault), [ADR-005](https://github.com/hivemine-ai/hive-vault), [ADR-007](https://github.com/hivemine-ai/hive-vault), [ADR-008](https://github.com/hivemine-ai/hive-vault) and the [Visibility Engine + Audit Log](https://github.com/hivemine-ai/hive-vault) tech spec.
- **New runtime env vars** (PRY-004): `HIVE_VISIBILITY_AUDIT_CANSEE_DENIALS` (default `false`) gates audit writes for `canSee` denials; `HIVE_AUDIT_DETAIL_MAX_BYTES` (default `4096`, clamped to the 4 KB schema ceiling) lets operators lower the per-event detail cap. The remaining audit env vars from the tech spec (`HIVE_AUDIT_RETENTION_DAYS`, `HIVE_AUDIT_PURGE_INTERVAL_HOURS`, `HIVE_AUDIT_PURGE_BATCH_SIZE`, `HIVE_AUDIT_QUERY_MAX_PAGE_SIZE`) ship with the Slice 1 purge job + paginated query.

### Security (v0.1.0 progress)

- **TOCTOU send/cascade fix** (PRY-010): `sendMessage`'s recipient-cell guard now runs INSIDE the message INSERT transaction. On Postgres the SELECT takes a `FOR SHARE` row lock so a concurrent `closeCellsByOwner` UPDATE blocks until the send commits, then the send observes `state='closed'` and aborts with `RECIPIENT_UNREACHABLE`. SQLite's single-writer model serializes implicitly. Closes the bounded race flagged by the `/security-review` of PRY-003.
- **Per-listener exception isolation in `events.emit`** (PRY-010): each subscriber now runs in its own try/catch — both synchronous throws AND async (Promise) rejections are caught and forwarded to a per-emit `onError` sink, never propagating to the caller or surfacing as `unhandledRejection`. A failing listener cannot prevent others from running and cannot roll back the message INSERT.
- **Always-allow `stubVisibilityEngine` replaced by the real engine in production wiring** (PRY-004): the composition root now constructs `createVisibilityEngineForProduction` so every `sendMessage` call evaluates the product matrix against the recipient and audits denials. The stub remains exported for Cell Store unit tests only; production code paths must use the factory. Closes the bounded "stub-as-engine" surface that PRY-002 + PRY-003 shipped with.
- **Privacy-uniform denials at the wire** (PRY-004): every `canSend` denial collapses to a boolean `false` for the caller (Cell Store maps it to `RECIPIENT_UNREACHABLE`). The discriminating `reason_code` (e.g. `worker_to_other_owner_worker`, `recipient_not_found`, `cross_hive`) lives only in the audit log, never on the wire — preserves the anti-enumeration property declared by the product spec.
